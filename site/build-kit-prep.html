The plugin

One kit, published
on GitHub.

PlumHQ/insurwreck-kit is a public repository with a shared core and one adapter per agent. It holds no secrets — it only talks to the credential desk.

01

Introduce

Opens with an ASCII intro in the terminal and sets the frame: bring one real problem, leave with a working prototype.

02

Register

Asks for name, work email, and a two-sentence idea brief, then posts the answers to the roster. Organizers see who is coming and what they want to build.

03

Provision

Verifies the email with a one-time code, fetches the credential bundle, writes it to the project environment, wires the Supabase and Vercel MCP servers, and smoke-tests each service: deploy a hello page, create a table, send one email.

04

Tailor

Reads the idea brief and prepares the relevant lane. Email parsing in the brief sets up the AgentMail inbox and a starter n8n workflow; a dashboard idea scaffolds the Vercel project first.

The credential desk

Delivery,
not minting.

The experience we want — verify once, everything works — does not require minting every token live. It requires one gate that delivers a per-participant bundle. Behind the gate, each service does whatever its API actually allows: some credentials are created at that moment, some the night before. The participant cannot tell the difference, which is the point.

The desk is a small API deployed on Vercel with its roster in Supabase and one-time codes sent through Resend — the same stack participants build on. Composio was considered and set aside: it connects agents to accounts users already own, and does not mint credentials on infrastructure we own centrally.

Desk endpoints

POST /auth/otp      work email → six-digit code via Resend
POST /auth/verify   code → short-lived session
POST /provision     session → credential bundle + roster entry
GET  /roster        organizers → names, emails, idea briefs
01

The plugin repo is public plumbing and holds zero secrets. Master keys live only in the desk's environment.

02

Codes go to @plumhq.com addresses only, and every key carries minimum scope: sending-only Resend keys, per-project Supabase keys, never org tokens.

03

Everything is time-boxed. A revoke sweep runs after the event; nothing outlives the hackathon by default.

Provisioning

What mints live,
and what cannot.

Five services, three honest answers. The desk hides the difference; this table is where the work is.

Service Live minting The path
SupabaseDatabase Mints live The Management API creates a project per participant on demand and returns the URL with anon and service keys. Confirm org project quotas against the roster.
ResendEmail delivery Mints live The master key mints scoped, sending-only API keys against one shared hackathon domain.
AgentMailEmail parsing Mostly An inbox per participant via API is native to the product. Per-user key minting needs verification; the fallback is one org key with per-user inboxes.
VercelDeploys and previews Pre-provision No API mints tokens for other users, and none is needed: everyone is pre-invited to the team, and the plugin walks through the vercel login device flow.
n8nWorkflows Pre-provision Users are pre-created on a shared instance, and the desk hands each participant their login and personal API key. Hosting choice is decision 03.

Slack and WhatsApp stay out of the bundle. They remain optional and approval-gated on the day, as on the attendee page.

Stage one · Set up

Five steps.
Tick each one.

Your ticks are saved on this device, so you can see your own progress while we go through it together.

  1. 01

    Paste one line

    On a Mac press ⌘Space, type Terminal, hit enter. Then paste this and press enter.

    Terminal 
    $ curl -fsSL https://insurwreck-desk.preview.plumhq.com/go | bash

✓ Ghostty installed
✓ Claude Code installed
✓ node and Salesforce CLI ready
✓ Insurwreck toolkit installed
✓ Project folder at ~/insurwreck

    On a Windows laptop press the Windows button, type Terminal, hit enter. Then paste this and press enter.

    Terminal 
    $ irm https://insurwreck-desk.preview.plumhq.com/win | iex

✓ Ghostty installed
✓ Claude Code installed
✓ node and Salesforce CLI ready
✓ Insurwreck toolkit installed
✓ Project folder at ~/insurwreck

    Three to five minutes, with a tick per step. If it asks for your Mac password, that's the installer needing permission to install software — type it and carry on. Safe to run twice; it skips whatever is already done.

  2. 02

    Tell it who you are

    The installer ends by printing a line to paste, finishing in claude --permission-mode auto. Paste that. Nothing happens on its own after that — once the agent starts, remember to type /insurwreck:start in the same terminal:

    Claude Code 
    > /insurwreck:start

? Your name   →
? Work email  → your @plumhq.com address
? Idea brief  → two sentences are enough

    Then it emails you a six-digit code from insurwreck@badge.plumhq.com. Paste it back. Check spam the first time.

    No idea yet? Say "still exploring". It's a valid answer and we'll help you pick one later.

  3. 03

    Wait while it builds your kit

    This is the slow bit — a minute or two. It's creating real infrastructure in your name. Everything in the next section is being provisioned right now.

    Claude Code
    Creating your Vercel project…      ✓
Creating your Supabase project…    ✓
Minting model access…              ✓
Opening your agent inbox…          ✓
Wiring Plum data, workflows, login… ✓

Ready. Nothing for you to copy or paste.

    If a service says almost ready, that's normal — /insurwreck:status finishes it off later. It never asks you for a key.

  4. 04

    Quit it. Start it again.

    Close the window. Reopen your terminal. Paste the same launch line the installer gave you.

    This restart is what switches the Plum data on. Skip it and the data server will look broken — and you'll spend twenty minutes debugging something that isn't wrong.

    Why: the data connections read your tokens when the agent starts, and your tokens only came into existence a minute ago. This is the step people skip.

  5. 05

    Prove it works

    One command checks your whole setup and explains anything wrong in plain English.

    Terminal 
    $ iw-doctor

✓ Toolkit up to date
✓ Credentials found
✓ Plum data server responding
✓ Workflows connected
✓ Hosting ready

All good. You're set up.

    All green?

    You're done. Sit tight while we get everyone else there.

    Something red?

    Read what it says — it usually names the fix. "Restart" genuinely means restart. If it says a token was rejected, raise your hand; re-running won't help.

The harness · Safety nets

Three things you
don't have to think about.

Undo you never asked for

Every file change is quietly checkpointed. Say "go back to before that change" and it will.

Secrets stay out of code

Paste a real key into a file and it stops you, explains why, and puts it somewhere safe instead.

No catastrophic commands

Anything that would wipe your folder or throw away work asks what you actually meant.

None of this blocks you. It's there so one wrong keystroke doesn't end your day.

Your data

Real Plum data.
Handled carefully.

What you get

Ten read-only slices: claims, covered lives, support tickets, NPS, policy schedules and more. Ask for what you want — you don't need to know table names.

De-identified: no member names, ages banded, free-text notes stripped out.

Read this once

It is still confidential company data. Never screenshot it into Slack. Never put a raw row on a slide.

Aggregate numbers and charts in your demo are fine. Raw records are not.

Also useful: /insurwreck:status repairs anything unfinished.

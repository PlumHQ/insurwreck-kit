Authorized redirect URIs

Google exposes no API for an OAuth client's redirect URIs, so each participant's callback has to be pasted into the console by hand. Until it is, their sign-in button fails with redirect_uri_mismatch and nothing else about their setup is affected. Cap is ~100 URIs per client, so headcount is not a constraint.

When someone says…

"The Plum data server shows failed / red"
Expected before onboarding - the token doesn't exist yet. Have them run /insurwreck:start, then quit and restart Claude Code. If it persists, iw-doctor names which of three states they're in.
"I never got my code"
People tab → Get code. Reads it back to you directly.
"I've run out of model budget"
People tab → Raise budget. Applies on their next call, no restart. For scale: a whole app built and deployed cost $0.105.
"I need data none of the slices have"
First check it isn't a join they can do across two existing slices - that costs nothing. Otherwise use the publish-a-slice skill and publish the card id on the Data slices tab. Target five minutes.
"A slice genuinely can't answer my question"
Grant full data - raw read-only SQL over the whole warehouse, one person at a time, logged, revocable. They must restart Claude Code to see the tool. Not a switch to leave on.
"My setup half-finished / a service says pending"
/insurwreck:status repairs it from their side. If that fails, Repair setup on the People tab does the same server-side (admin key only).
"Sign in with Google doesn't work"
Google sign-in tab - their callback URI probably isn't registered yet.
"Salesforce won't connect"
First launch downloads the server and can time out; it works on the second. Needs sf org login web per person, and the CLI does not install on Linux/WSL2.
"Kula tools all fail"
No API key has been issued. The server connects but every call fails. Nothing the participant can fix.

Limits worth knowing before you promise anything

  • 500 rows through run_dataset, 2000 through bulk export. The 2000 is a Metabase ceiling and cannot be raised - the answer is an aggregated slice, not paging.
  • Everything is de-identified: no member names, ages banded, free-text diagnosis and ticket bodies removed. Org brand names are fine.
  • A participant's own agent shell is sandboxed on macOS and may not reach the network. Bulk downloads belong in their app code, or they run the curl themselves with !.
  • Data is confidential. No screenshots into Slack, nothing on a slide.

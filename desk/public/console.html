Runbook what to do when someone says…
"The Plum data server shows failed"
Expected before onboarding — the token does not exist yet. Run /insurwreck:start, then quit and restart Claude Code. Still failing? iw-doctor names which of three states they are in.
"I never got my code"
Get code on their row reads it back to you.
"I've run out of model budget"
Raise on their row. Applies on their next call, no restart. For scale: a whole app, built and deployed, cost $0.105.
"I need data none of the slices have"
First check it isn't a join across two existing slices — that costs nothing. Otherwise the publish-a-slice skill, then publish the card id above. Five minutes.
"A slice genuinely can't answer my question"
Grant full data: raw read-only SQL over the warehouse, one person at a time, logged and revocable. They restart Claude Code to see the tool. Not a switch to leave on.
"My setup half-finished"
/insurwreck:status repairs it from their side. If that fails, Repair does the same server-side.
"Sign in with Google doesn't work"
Their callback URI is probably not registered yet — see the section above.
"Salesforce won't connect"
The first launch downloads the server and can time out; the second works. Needs sf org login web per person, and the CLI does not install on Linux or WSL2.
"Kula tools all fail"
No API key has been issued. The server connects, every call fails. Nothing they can fix.

Before you promise anything

  • 500 rows through run_dataset, 2000 through bulk export. The 2000 is a Metabase ceiling and cannot be raised — the answer is an aggregated slice, never paging.
  • Everything is de-identified: no member names, ages banded, free-text diagnosis and ticket bodies removed. Org brand names are fine.
  • A participant's agent shell is sandboxed on macOS and may not reach the network. Bulk downloads belong in their app code, or they run the command themselves.
  • This is real member data. No screenshots into Slack, nothing on a slide.
